# 2026-10-12 正确性与 Redis 读取优化

基线：`c1a8dd9e097e7d9c053a373dfe90c846303de6ed`。本次仅修改工作区代码；没有连接生产 Redis、部署或迁移生产数据。

## 正确性

- `base/parsed` 使用统一的异步稳定 ID 解析。ID/Cookie 冲突以 ID 为准；非法 ID、已删除 ID、ID/名称冲突分别拒绝，不回退。已鉴权 ID 贯穿渲染、设备预览、缓存和 304，名称在请求中途重新分配时拒绝返回另一资源。
- 派生分发 token 改为 HMAC(master, JSON 编码的 `["pm-sub", 2, 资源类型, 稳定 ID, token_version]`)。类型包含 profile、subscription、collection、rule-set；旧记录的 token_version 默认为 1。公开名称查询仅在 Redis 内投影身份元数据，鉴权后才按 ID 读取正文（兼容旧内嵌正文）。删除重建同名资源不会继承原资源权限。
- 停止接受裸名称派生 token。master 和 SUB_TOKEN_PREV 的轮换机制保留；部署前应重新生成以前单独分享的旧式派生链接。`/meta` 的 subBase 等 master 链接仍是全局凭据。首页提供绑定当前 Profile 的派生链接。
- 本地规则集 URL 由服务器为每个规则集生成自己的资源凭据，不再沿用访问 Profile 的 token。
- 规则 revision 使用写入所提交的全局 CAS 代次，普通编辑提交打开表单时固定的 expectedRevision，冲突为 412，保留草稿。撤销同时比较完整状态，保护没有 revision 的历史记录和同秒写入。迁移、规则集改名级联、克隆等规则写入边界也更新 revision。
- 场景 dispatcher、规则批量操作、撤销、设备 CRUD/feature 和排序服务先规划候选与审计，再由一次 Lua CAS 落下配置、核心审计和撤销关联。原有预检继续执行；一个操作只能规划一次配置提交。分类标签属于提交后的辅助状态。
- 审计 JSON 保留原始字符串，防止 Redis cjson 把空数组重新编码为对象。审计 key 类型、撤销状态在配置写入前检查。
- 无配置 CAS 的操作仍批量保存规划阶段收集与返回的全部审计事件，并执行辅助写入；保留已生成的事件 ID。批次内按输入次序递增时间戳，避免 UUID 同分排序打乱先后；不承诺并发批次的全局执行顺序。
- 历史裁剪使用一个 Lua 操作选出并删除同一批 ID。清理失败不改变已提交操作的成功结果。
- 创建/批量/场景接口支持 `Idempotency-Key`，配置与重放回执同一次提交，回执保留 24 小时；相同 key 携带不同请求返回冲突；共用 ops 路由的场景和操作也纳入指纹。规则新增表单在失败后保留同一请求的 key。超出回执保留时间的重试不提供去重保证。
- 历史分页新增基于 `(ts, id)` 的不透明 cursor，浏览器使用服务端 nextCursor。同毫秒边界不漏记录；旧 before_ts 参数仍可读取，但不能保证同时间戳的完整分页。
- Profile 完整配置入口实现 base64/v2ray 节点导出，不支持的 format 返回 400。预览返回实际 rendered_at，缓存命中不伪造生成时间。

## 读取与缓存

| 路径 | 改动与边界 |
| --- | --- |
| 工作台启动 | `/api/v1/bootstrap` 从同一份诊断快照返回状态和 Profiles。已配置状态按 configVersion 缓存 60 秒；初始化、修复依旧严格检查。 |
| Profile 切换 | 保留工作台与文档，更新标签页稳定 ID，重新挂载作用域内内容；草稿确认和失败后的写入阻断保留。 |
| 首页 | `/api/v1/dashboard` 在 Redis 内投影计数、组类型、设备数量、近期事件和渲染摘要，规则数使用 HLEN。不会拉取完整规则、节点或本地订阅正文到应用。运行健康仍按当前订阅指纹校验。 |
| 规则页面 | 搜索/翻页只请求规则列表，汇总来自相同稳定快照；字典与搜索分页解耦。 |
| 规则存储分页 | 每个配置版本/查询建立短期有序 ID 索引。首次查询仍扫描一次；后续页用 MGET 清单、ZRANGE ID、HMGET 当前页，再检查版本。任意文本搜索首次仍是完整匹配扫描，不把 HSCAN 当有序分页。 |
| meta | 原子读取 base 元数据和正文存在性，不传输正文；两个 key 都存在才算已初始化。 |
| 本地订阅 | 新保存通过原有配置/ordinal CAS 原子写入独立正文 key，元数据 Hash 不再保存正文。详情读取原子拼接；列表与按名查找走元数据摘要。旧内嵌正文继续只读兼容，重新保存时才转为新布局。未批量改写生产旧数据。 |
| 配置预览 | 配置页使用 `view=content`，不下载完整节点名称、按来源节点列表、碰撞明细。其他调用方默认完整视图兼容。 |
| 渲染变体 | Profile 和设备缓存按编译 epoch、URL 变体与凭据代次哈希分槽，结构读取和预览互不覆盖。 |
| 无关 Profile 写入 | 保留全局 CAS；缓存版本变化后重新读取并比较依赖指纹，依赖未变且产物仍新鲜时复用，不重新获取上游或编译。仍有一次依赖复核读取，未引入另一套持久化细粒度失效计数器。 |
| 条件订阅请求 | YAML 的 If-None-Match 先读取轻量 manifest，命中可直接 304，不读取完整缓存正文。base64 和设备响应仍走自身产物处理。 |
| 多 Profile 预检 | 一次共享源操作按版本复用共享库快照，保留排序执行和同一编号规划会话，不无约束并行化。 |
| 测量 | API 增加 Server-Timing：total、storage（逻辑存储等待时长之和）、storage_calls。并发等待会重叠；这些不是 REST HTTP 请求数，不把 SDK 自动批处理算成多次网络请求。无 key、URL、token 或节点数据日志。 |

没有更换数据库或修改 Vercel 部署区域。配置规模较小的 Profile/规则集元数据仍可使用 HGETALL；本次没有为了避免每一个 HGETALL 增加永久名称索引。旧数据正文迁移与持续维护索引不在读请求中偷偷执行。

## 发布与降级边界

首次用新版保存本地订阅后，正文将从元数据记录移到独立 key。旧版应用不读取该 key，因此不能直接回滚旧版程序，也不能让新旧版本同时服务同一数据库。上线前必须阻断旧部署（含连接同一 Redis 的预览部署）的读写入口，并备份元数据和正文；不能仅依赖切换默认部署域名。

需要回退程序时，只能选择仍支持拆分正文布局的兼容版本。若必须降级到旧布局版本，应先停写，在隔离副本上实现并验证正文回填迁移，确保每个本地订阅的独立正文完整恢复到元数据的 content，再安排生产迁移；本 PR 不包含该逆向迁移工具，不能把“独立正文仍在”当作已经可安全降级。旧式派生链接的重新生成是另一项独立的上线要求。

## 验证方法

本次已执行：155 个测试文件、3,051 项测试全部通过（包含下述 13 项隔离 Redis 集成测试）。Node 22 类型检查、lint 和生产构建通过；此前本地生产构建的 19 项浏览器回归通过，后端使用合成数据；本轮审计分支修复未重复运行浏览器测试。

- `npm test`：仓库完整离线单元/服务/路由测试。
- `npm run typecheck`、`npm run lint`、`npm run build`，使用 Node 22。
- `npx playwright test e2e/audit-fixes.spec.ts`：原有浏览器验收；新增不整页重载、搜索不重复拉字典、revision 冲突保留草稿。
- `tests/repos/auditRedisIntegration.test.ts` 使用自行启动的隔离 Redis（Unix socket、无持久化），不依赖 Upstash 或生产环境。运行方式：

```sh
PM_REDIS_SERVER=/path/to/redis-server \
PM_REDIS_CLI=/path/to/redis-cli \
npm test -- tests/repos/auditRedisIntegration.test.ts
```

未提供 Redis 二进制时，该集成文件显式跳过。覆盖原子审计、CAS 拒绝、重试回执、空数组、撤销关联、500 事件仅两次 eval、同毫秒完整分页、精确保留 1000 条、1001 条规则的页面实体读取、首页投影、本地正文拆分/冲突/删除/旧布局兼容。

性能证据是调用结构、读取粒度和合成数据传输量；不把本地结果声称为生产延迟改善。Vercel 冷启动、函数/数据库区域距离和真实上游耗时仍需部署后通过 Server-Timing 与浏览器瀑布测量。

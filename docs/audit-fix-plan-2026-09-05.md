**ProxyManager 审计问题修复计划 · 2026-09-05**

状态：已实施，最终验证记录见[修复记录](./audit-fixes-2026-09-06.md)。依据[审计报告](./audit-2026-09-05.md)，覆盖 F01–F09、U01–U05 共 14 项。以下保留实施时采用的范围与验收约定。

目标是让页面显示的配置与实际写入目标一致，保留未提交草稿，使批量操作完整提交，并补齐规则管理、手机布局和扩展写回流程。按下面 6 个批次推进，每批可独立评审、验证和发布。P1 修复完成后即可先行发布，无需等待全部界面调整。

| 2 | F02、F03、F04 | 编辑器刷新与导航过程中保留草稿 | 批次 1 的作用域与切换入口 |
| 3 | F06、F07 | 规则批量请求语义明确、策略组排序原子提交 | 批次 1；复用现有预检/CAS |

**已经选定的实现方向**

| 决策 | 本轮采用的方案 | 原因 |
| --- | --- | --- |
| 请求作用域 | Web/扩展使用稳定 profileId；保留已有 profile 名称参数兼容旧调用方 | 避免 cookie、标签页和重命名改变写入目标 |
| 草稿保存 | 草稿保存在当前编辑会话内；后台刷新不卸载编辑器 | 先解决丢失路径，避免把配置凭证额外持久化到浏览器 |
| 保存期间输入 | 允许继续编辑；保存响应只确认已提交的版本 | 让慢请求不会覆盖后续输入 |
| 同批次重复规则 ID | 整批返回 422，要求调用方先合并为一个 patch | 避免产生从未持久化的中间审计状态，保留现有逐实体撤销方式 |
| 策略组排序 | 新增专用排序入口，一次预检、一次 CAS | 一个用户动作对应一个完整写入 |
| 规则列表 | 服务端分页与搜索，默认每页 100 条；统计单独汇总 | 覆盖全部数据，避免一次加载全部规则 |
| 预览失败 | 保留上次成功内容并明确标注；普通导出禁用，提供明确的“导出上次成功版本”操作 | 用户知道导出的具体版本 |
| 分发开关 | 改成“启用/停用订阅源（或聚合）”，展示影响范围 | 当前数据模型没有独立的公开访问权限，此轮纠正文案与操作表达 |
| 扩展历史 | 新记录固定保存 backend origin、profileId 和显示名称 | 改设置后撤销仍须作用于原始实例与配置 |

独立的分发权限、每资源令牌、持久化草稿恢复属于额外产品能力，不作为这 14 项问题的修复前提。

**批次 1：固定作用域，修复跳转校验**

主要涉及 [profileScope.ts](../web/lib/profileScope.ts)、[ProfileContext.tsx](../web/components/profile/ProfileContext.tsx)、[api.ts](../web/lib/client/api.ts)、Sidebar、所有 Profile 相关调用方、AI 客户端调用链和登录页。

实施内容：

1. 服务端增加显式 `?profileId=<UUID>`，通过 ID 解析 Profile。有效 ID 优先于偏好 cookie；同时传入的 name 与 ID 不一致时拒绝请求。非法 ID 返回 400，不存在返回 404，均不得回退到 default。
2. 保留旧 `?profile=<name>` 和旧调用方的 cookie/default 兼容入口。参数省略与参数无效必须区分。
3. 增加要求传入 Profile ID 的客户端请求封装。迁移 base、anchors、policies、rules、proxy-groups、场景操作、预览衍生读取及共享资源页面上的 Profile 统计。按 ID 路由的设备/配置详情继续使用路径中的目标 ID。
4. 编辑会话固定绑定确认过的 ID；缓存、异步响应、预览数据都按该 ID 隔离。切换后迟到的旧请求不得覆盖新页面。当前 Profile 被删除时进入可恢复的错误态，保留草稿，禁止静默改写到 default。
5. 切换 Profile 先经过当前草稿的离开判断，再更新偏好与导航。取消切换时不改变 cookie、当前 ID 和页面数据。成功保存后的主动导航只跳过该次已确认的离开提示，避免双重确认或意外历史回退。
6. AI 会话/单轮操作显式接收 Profile ID，移除 browser tool 读取全局 cookie 决定目标的行为；确认卡继续使用服务端已绑定的原 Profile，并展示其名称。已有确认令牌不得因界面切换而重新指定目标。
7. 提取共用站内跳转校验：解析 URL、比较 origin、拒绝非法协议/反斜杠/控制字符，返回规范化的 pathname、search 和 hash。登录页和 Profile 切换后的 redirectTo 复用它。
8. 在受认证的 meta 响应中增加可检测的 Profile ID 作用域能力标识，供后续扩展识别服务端兼容性；更新 Zod/OpenAPI 和调用示例。

验收：

- 两个标签页分别编辑 A、B，互相切换后各自保存仍命中原 ID；包括两份 base 内容完全相同的情况。
- 有草稿时取消切换，cookie 和目标 ID 均不变；仅出现一次确认。
- Profile 重命名不改变编辑目标；删除、首次加载失败或作用域不明时无法写入。
- AI 的读取、预览、确认执行在同一 ID 下；账户共享操作维持实际的共享作用域。
- 登录 next 的正常站内路径可用；`//host`、`/\\host`、控制字符和编码变体不能跳到外站。

**批次 2：统一编辑器草稿与离开保护**

主要涉及 ProfileContext/ProfileScopeBoundary、ProfileBindingBar、BasePage、useUnsavedGuard，以及规则、规则集、订阅、策略组、Profile/设备编辑器。

实施内容：

1. 拆分首次加载、后台刷新、刷新失败等状态。首次未确认作用域时继续阻止编辑器进入；已确认同一 ID 后的后台刷新保持组件实例。
2. 保留当前“作用域未经确认时禁止保存”的约束。后台刷新失败时展示错误和重试，保存按钮、快捷键、程序化写入统一暂停，但草稿仍可查看和复制。
3. 节点来源变更成功后局部更新 Profile 数据；必要的后台重取不能清空 base 草稿。明确提示来源选择立即保存，YAML 仍有独立的未保存状态。
4. Base 保存记录提交内容、编辑版本和提交 ID。成功响应更新该次提交的已保存基线及 ETag；若期间有新输入，保留新草稿并继续显示未保存。后续保存使用新的 ETag。
5. 处理保存失败、412、成功后辅助刷新失败：保留草稿；辅助刷新失败不能把已经成功的提交伪装为保存失败。提供重新读取远端的明确动作，覆盖草稿前经过保护。
6. 将草稿保护扩展为“登记 dirty 状态 + 受保护的离开动作”。侧栏导航、Profile 切换、浏览器返回、同页实体切换、新建、取消编辑与程序化路由共用判断。
7. 同一编辑会话只由一个协调入口管理 history/beforeunload，避免多个子表单各自 push/back。本地实体切换不制造多余历史记录，支持 React Strict Mode。
8. 接入规则 RuleForm、规则集列表切换、订阅/聚合新增与编辑；同时检查其他已使用 guard 的编辑器，覆盖内部按钮切换和关闭面板路径。

验收：

- 修改 YAML 后切换来源，草稿和光标不因资料刷新消失。
- 保存期间输入第二版：第一版保存成功，第二版仍留在编辑器且保持 dirty；再次保存成功。
- 412、网络失败、刷新列表失败不丢草稿，不绕过写入门禁。
- 从规则集 A 切到 B、关闭表单、侧栏跳转、浏览器返回均能取消离开；取消后草稿仍在。
- 保存完成后正常返回不会额外弹窗、连续退两页或积累重复 history entry。
- 打开多个编辑区域时不重复确认；抽屉关闭后再打开保留其预期状态。

**批次 3：明确批量语义，原子提交排序**

主要涉及 [schemas/batch.ts](../web/schemas/batch.ts)、规则 batch 路由、proxyGroupService、profileConfigMutationService、策略组列表、OpenAPI 和审计投影。

F06 的实施约定：

- 对 update/delete 的目标 ID 做整批去重校验。相同 ID 出现两次时，返回带重复操作索引的结构化 422，且执行任何预检、写入和审计之前结束。
- 调用方需要同时更改 policy 和 note 时合并成单个 patch；查找 Web、扩展和插件的 batch 生成点，确保不依赖重复 ID。
- 不同 ID 保留原有 200/207 逐操作结果协议和最终预检门禁；成功操作的最终候选一次提交。
- 给错误增加可执行说明：“同一批次每条规则只允许一次操作，请合并修改”。

F07 的实施约定：

- 增加 `POST /api/v1/proxy-groups/reorder?profileId=...`，请求包含 `expectedVersion` 和当前 Profile 全部策略组的 `orderedIds`。
- 列表响应增加与列表同一稳定快照对应的 configVersion，不能在读完旧列表后随意附上新版本。
- 服务端校验版本、ID 唯一性、完整性和归属；从版本一致的快照重建最终 rank，复用最终配置预检及 CAS。冲突返回 412，整个顺序不变。
- UI 在同分区拖拽时生成完整序列，未移动组保持原相对顺序。搜索/筛选期间不允许排序；一次拖拽只发一个请求，请求期间禁用下一次排序。
- 成功后用服务端结果替换临时顺序；失败时恢复已确认顺序并保留错误提示，不自动重放旧排序。
- 记录同一次排序的 before/after。若本批未实现安全的整批逆向操作，审计明确标注不可一键撤销，不能给出逐组撤销会破坏整体顺序的入口。
- 现有 proxy-groups/batch 保留创建用途。

验收：

- 重复 update、update+delete、重复 delete 都在写入前返回 422；无存储与审计副作用。
- 合并后的 patch 同时保存多个字段，普通不同 ID 批次行为保持兼容。
- A=10、B=20 的交换最终为 A=20、B=10；只有一次版本增长。
- 与其他编辑并发时排序全部成功或全部失败，没有重复 rank 的部分结果。
- ID 缺失、混入其他 Profile、重复 ID、过期版本不能写入。
- 保持最终 MATCH 终结规则、跨锚点验证与缓存无副作用预检约束。

**批次 4：补齐分页、统计和预览导出**

主要涉及 RulesPage、rules 路由/服务、策略组引用统计、规则集引用展示及 ConfigPage。

F05 的实施约定：

1. 列表改为服务端分页，每页默认 100 条，保留接口 500 的上限。上一页、下一页、当前范围和筛选后总数可见。
2. anchor、policy、type、enabled 与搜索统一在服务端执行。补齐现有 UI 的修饰符搜索语义；输入短暂防抖，筛选改变时回到第一页，取消旧请求或忽略过期响应。
3. 对相同 rank/排序值添加稳定的 ID 次序，保持引擎既有锚点与 MATCH 语义。
4. 新增 `GET /api/v1/rules/summary?profileId=...` 汇总总数、启用/停用、锚点、policy 与 RULE-SET 引用，策略组引用数不再依赖第一页。汇总与列表各自标明作用域，失败时展示“统计暂不可用”。
5. 共享规则集页面的统计明确写成“当前配置引用”；不能仅根据当前 Profile 的零引用宣称全账户“未被使用”。全局删除检查继续由服务端决定。
6. 新增 `POST /api/v1/rules/[id]/move?profileId=...`，方向和 expectedVersion 由客户端传入，服务端从完整同锚点序列找到相邻规则并原子交换。避免翻页边缘只能和本页规则交换；筛选激活时保持禁用并解释原因。
7. 删除/新增后重取总数与有效页码；最后一页删空时回到前一页。未保存表单在翻页前经过批次 2 的保护。

F09 的实施约定：

- 预览状态区分 loading、ready、refreshing、stale/error，保存最近成功的内容、生成标识、时间与 Profile ID。
- 重新生成期间及失败后，普通“复制 YAML / 下载 YAML / 复制订阅地址”遵循同一 readiness 判断。
- 有旧内容时仍可查看，但明确显示“上次成功版本，最新检查失败”，提供单独命名的旧版本导出动作。
- Profile 改变即取消/隔离旧预览，不能给 B 的文件名或链接配上 A 的内容。
- 剪贴板失败有用户可见反馈，不能宣称复制成功。

验收：

- 501 条、1,001 条规则均可完整分页；准确搜索、编辑、停用和删除最后一条。
- 搜索值、备注、修饰符及 enabled 过滤与界面描述一致。
- 慢查询结果不能覆盖用户后输入的查询；总数不因删除后遗留旧 state 出错。
- 排序跨页找到真实邻居，失败不产生半次交换，MATCH 不能越过终结约束。
- 超过 100/500 条后的引用仍统计准确，未知状态不会显示为零。
- 预览 404、422、502、网络失败时普通导出不可用；旧版本导出清晰注明对象，切换 Profile 后不会串用。

**批次 5：统一手机顶栏与抽屉**

主要涉及 PageChrome、Topbar、Sidebar、DistributeDrawer、Base/Config Inspector、AssistantPanel 及共用样式。

实施内容：

1. PageChrome 增加结构化的主要/次要操作配置，逐页迁移现有按钮；手机下固定保留导航、页面标题/简短作用域、主要动作和“更多”入口。
2. 校验、主题、助手等次要操作进入明确的更多菜单。按钮禁止 flex 收缩，触摸区域至少 40×40px，长 Profile 名截断且可查看完整名称。
3. 建立共享模态 Drawer/Dialog 基础组件，优先用原生 dialog 的模态能力，配合统一样式与 Portal；统一初始焦点、Tab 范围、Escape、背景不可交互、滚动锁定和关闭后焦点恢复。
4. 对有草稿的关闭操作调用批次 2 的离开保护；关闭 AI 抽屉保持已有流式任务与会话状态。不要通过无条件卸载内容制造新的草稿丢失。
5. 桌面常驻侧栏/检查栏保持普通区域；进入手机断点才使用模态行为，跨断点解除背景锁定。
6. 关闭态不渲染投向页面的阴影，不可进入键盘焦点；统一遮罩、z-index、浅深色 token 和 reduced-motion。
7. 多浮层情况下仅最上层处理 Escape，关闭后恢复到发起动作，避免焦点回到已卸载元素。

验收：

- 在 1440、1100、600、375px 检查基础配置、规则、订阅和设备详情；测试默认名称与长名称。
- 375px 下无必须靠隐藏横向滚动寻找的主要动作，导航与按钮达到触摸尺寸。
- 键盘可进入、循环操作并关闭抽屉；不能触发遮罩后的保存/校验。
- 关闭/断点切换后焦点与页面滚动恢复，关闭的检查栏没有残留阴影。
- 浅色、深色和减少动画模式行为一致；编辑中的抽屉不会无提示丢草稿。

**批次 6：纠正来源开关，给扩展绑定 Profile**

U04 主要涉及 DistributeDrawer、订阅/聚合列表和引用关系读取。

- 将“公开访问”改为“来源状态”；开关明确表示“启用订阅源/启用聚合”。
- 展示直接绑定的 Profile、聚合成员关系及相关使用范围，说明停用会影响节点使用，不只改变分发链接。
- 复用服务端的来源使用关系计算；需要补充读取接口时只返回安全的名称/ID/关系，不输出订阅凭证。读取失败展示“影响范围暂不可用”，不能显示为无人使用。
- 对有引用的停用展示具体影响；服务端最终预检照常拦截无效配置，不用前端关系快照代替写入时校验。
- 模板化错误文案区分“来源无法停用”和“链接未生成”，复制/打开链接与来源状态保持一致。

U05 主要涉及 extension settings、backend、messages、background、options、popup 和 recent-writes。

- 增加 Profile 列表读取及选择，保存稳定 profileId；名称只用于展示。旧设置升级时明确解析名为 default 的 Profile，找不到则要求选择。
- 先检测服务端对显式 profileId 的支持；旧服务端缺少能力标识时显示升级提示并阻止写回，避免未知参数被忽略后误写 default。
- policies、anchors、查询、单条/批量写入均显式传目标 ID；popup 发起动作时固定实例 origin 和 Profile，background 校验该目标后执行。
- 切换 Profile 时重取 anchors/policies；清除不适用的选择和待提交内容，不自动把一个配置的策略名套到另一个配置。
- 成功记录保存 origin、profileId、当时名称；撤销从该记录读取目标，不能读取当前选择替代。
- 旧历史缺少来源信息时标记“原始目标未记录”，禁用不安全的一键撤销。若当前连接的实例与记录不同，先提示连接原实例，不把当前密钥发送给历史地址。
- 扩展显示规则写入成功与客户端重载结果时继续分别反馈；并不把 Profile 选择视为已替用户切换本地客户端配置。

验收：

- 来源关闭动作明确表达影响，直接绑定来源的禁用失败有可读原因，引用读取失败不会给出“无影响”的结论。
- office 存在而 default 不存在的实例仍可明确选择并写入 office。
- anchors、策略选择、批量写回与撤销均对应同一 Profile。
- 切换设置后撤销旧记录仍命中原目标，或明确阻止，不误删当前 Profile 的规则。
- 旧设置、旧历史、Profile 重命名/删除、旧服务端、网络失败均有可恢复状态。
- 真实 Chrome 扩展验收仅连接隔离测试实例/模拟 controller，确认通过后再做实际客户端验证。

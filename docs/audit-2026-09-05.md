**F01 · 固定每个编辑页面的请求作用域**

位置：[ProfileContext.tsx:141](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/components/profile/ProfileContext.tsx#L141)、[基础配置保存:161](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/base/page.tsx#L161)、[服务端作用域解析:42](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/lib/profileScope.ts#L42)。

有两条独立触发路径：

1. 在 `default` 的基础配置页编辑 YAML，切换到 `office`，在浏览器“离开网站”提示中取消，再保存。
2. 标签页 A 保持 `default`；在标签页 B 切换到 `office`，随后回到 A 保存。

两种情况下，实测页头仍显示“配置 · default”，但 PUT 请求都是：

```text
PUT /api/v1/base
Cookie: pm.active_profile=office
请求 URL 没有 ?profile=default
```

切换函数先写共享 cookie 再触发刷新，取消刷新不会撤销 cookie；其他标签页也不会同步自身 React 状态。服务端按请求时的 cookie 解析作用域。规则创建和策略组创建也使用这类隐式作用域。Base 的 ETag 只校验内容版本，如果两份配置原本相同（例如克隆后），它不能阻止写入错误的 Profile；内容不同时可能表现为 412。

建议：所有 Profile 相关请求显式携带页面绑定的 Profile 标识；cookie 只保存下次访问的偏好。离开草稿的决定应发生在切换状态之前。补充多标签页和取消切换的回归测试。

**F02 · 更新节点来源不应卸载 YAML 编辑器**

位置：[ProfileBindingBar.tsx:90](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/base/_components/ProfileBindingBar.tsx#L90)、[ProfileContext.tsx:103](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/components/profile/ProfileContext.tsx#L103)、[ProfileScopeBoundary:255](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/components/profile/ProfileContext.tsx#L255)。

复现：在基础配置末尾增加 `# UNSAVED-BINDING-TEST`，不保存，直接从“节点来源”下拉框选择订阅源。浏览器结果为：确认对话框 0 次、Base 保存请求 0 次、重新出现的编辑器中草稿消失。

来源 PATCH 完成后调用共享 `reload()`，把 `loading` 设为 true；作用域边界因此返回另一棵组件树，直接卸载 BasePage。重新加载时编辑器读回已保存内容。页面没有发生导航，离开页面保护无法阻止这次卸载。

建议：区分首次确认作用域与后台刷新；同一 Profile 的资料刷新保留编辑器实例和草稿，必要时暂时禁用提交。来源变更可局部更新上下文。

**F03 · 保存回读会覆盖请求期间的新输入**

位置：[基础配置保存:155](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/base/page.tsx#L155)、[基础配置回读:83](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/base/page.tsx#L83)。

复现：提交含 `# first-draft` 的内容，将响应延迟 800ms，在返回前改为 `# NEWER-DRAFT`。返回后服务端模拟存储和编辑器都只剩 first-draft，NEWER-DRAFT 消失。

保存时只禁用了操作按钮，编辑器仍可输入；成功后 `load()` 无条件执行 `setContent(res.data.content)`，覆盖较新的本地草稿。

建议：记录提交时的草稿版本；响应只更新已保存基线和 ETag，只有本地草稿未继续变化时才替换编辑内容。若采用保存期间锁定编辑器，应提供清晰状态。

**F04 · 草稿保护未覆盖同页实体切换和规则表单**

位置：[规则集选择:268](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/rule-sets/page.tsx#L268)、[规则表单:690](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/rules/page.tsx#L690)、[useUnsavedGuard.ts:30](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/lib/client/useUnsavedGuard.ts#L30)。

复现一：编辑规则集 A 的内容，点击规则集 B，再点击 A。结果没有确认提示，没有 PATCH，草稿恢复为原始内容。选择按钮直接修改 selectedId，卸载了持有草稿的组件；通用 guard 只拦导航，不能拦这种按钮切换。

复现二：新增规则时输入域名，直接点击侧栏“基础配置”，页面跳转且没有确认提示。RuleForm 没有使用草稿保护。

建议：将实体切换、取消编辑、创建新实体和路由离开统一接入草稿保护；在父层维护当前编辑器的 dirty 状态，或按实体 ID 暂存草稿。订阅新增/编辑表单也应纳入相同检查。

**F05 · 规则列表分页没有完成，搜索只覆盖已加载数据**

位置：[规则列表加载:87](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/rules/page.tsx#L87)、[前端搜索:108](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/rules/page.tsx#L108)、[列表页脚:485](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/rules/page.tsx#L485)。

界面固定获取前 500 条，然后只在本地数组筛选。虽然页脚会显示“已加载 500 / 共 501 条”，却没有下一页或加载更多入口。模拟 501 条数据时，搜索第 501 条只显示“没有匹配当前筛选条件的规则”，且没有发出新的规则查询请求。

这会让后续规则无法在界面编辑、停用或删除，搜索结果也容易被误读为规则不存在。

另一个相关位置：[useProxyGroupsData.ts:71](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/proxy-groups/_lib/useProxyGroupsData.ts#L71) 未传 limit，按规则 API 默认值只拿 100 条，却用其计算策略组的规则引用数，可能低估引用。

建议：采用服务端分页与搜索，明确展示筛选后的总数。引用统计应由服务端聚合，或完整遍历分页；不能用第一页代表全集。

**F06 · 同批次重复更新同一规则时，早先修改被悄悄覆盖**

位置：[rules/batch/route.ts:99](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/api/v1/rules/batch/route.ts#L99)、[写集合并:70](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/lib/repos/profileConfigMutationRepo.ts#L70)。

复现：对原本 `policy=DIRECT` 的同一个 rule ID 发送：

```json
{
  "ops": [
    { "op": "update", "id": "<同一个有效 UUID>", "patch": { "policy": "REJECT" } },
    { "op": "update", "id": "<同一个有效 UUID>", "patch": { "note": "new-note" } }
  ]
}
```

实际路由返回 200，两项均宣称成功，但最终候选为 `policy=DIRECT, note=new-note`。每次更新都从批次开始时的 existingMap 读取旧记录；第二个全量 merged 对象重新带回旧 policy。按 ID 合并写集时，后一个对象覆盖前一个。

建议：按操作顺序维护批次内候选 Map，并从最终候选生成写集与审计；或者在 schema/规划阶段明确拒绝同一 ID 重复出现。更新和删除混合的批次也需要定义顺序语义。

**F07 · 策略组拖拽排序会和自身请求发生版本冲突**

位置：[策略组拖拽提交:218](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/proxy-groups/page.tsx#L218)、[patchProxyGroup:219](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/lib/services/proxyGroupService.ts#L219)、[preflightAndCommitProfileChanges:29](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/lib/services/profileConfigMutationService.ts#L29)。

一次拖拽用 Promise.all 对每个变更的组分别 PATCH，每个 PATCH 又读取相同的全局 configVersion 并各自执行 CAS。并发请求读取到同一版本时，第一个提交会增加版本，后面的请求因版本不匹配失败。

隔离存储的服务复现：A.rank=10、B.rank=20，同时提交 A→20、B→10，结果一项成功、一项版本冲突，最终两项 rank 都是 20。UI 虽然会提示失败并重新加载，但这不能完成一次应当整体提交的排序。

建议：增加原子的批量排序入口，一次构造最终顺序、一次预检、一次 CAS；现有 proxy-groups/batch 接口仅支持创建，不能直接当排序接口使用。

**F08 · safeNext 允许跳转到站外地址**

位置：[login/page.tsx:13](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/login/page.tsx#L13)。

`/^\/(?!\/)/` 只排除了两个正斜杠，没有处理浏览器对反斜杠的 URL 规范化。访问：

```text
/login?next=%2F%5Caudit.invalid%2Flanding
```

已有本地登录状态时，实际浏览器发起了到 `http://audit.invalid/landing` 的跳转；测试已拦截该请求。登录成功路径复用同一函数。

影响为可借本站登录 URL 跳转至任意外站，可用于钓鱼跳转；本次没有发现此路径直接泄露 ADMIN_KEY。

建议：使用 URL 解析后比较 origin，并只返回同源的 pathname/search/hash；处理反斜杠与控制字符。加入协议相对 URL、反斜杠和编码输入用例。

**F09 · 预览出错后仍可导出旧配置**

位置：[配置预览错误分支:55](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/config/page.tsx#L55)、[下载按钮:188](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/config/page.tsx#L188)。

复现：先成功生成预览，再令“重新检查”返回 502。界面显示“配置暂不可用”并隐藏 YAML 正文，但“下载 YAML”和“复制 YAML”仍然可用，导出的是上一次成功的旧内容。

**U02 · 抽屉应接管并恢复键盘焦点**

**U03 · 关闭状态的检查器阴影仍然遮挡编辑区**

位置：[base.module.css:242](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/base/base.module.css#L242)。

手机下的检查器始终挂载，只通过 translate:100% 移出屏幕，却一直保留 `-24px 0 64px rgba(0,0,0,.4)` 的向内阴影。实测关闭状态下左边缘在内容视口之外，阴影仍覆盖编辑区右侧，形成大面积灰黑遮挡，容易被误认为存在未关闭的浮层。

**U04 · “公开访问”文案与实际操作范围不一致**

位置：[DistributeDrawer.tsx:131](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/components/DistributeDrawer.tsx#L131)、[订阅开关:378](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/app/%28authed%29/subscriptions/page.tsx#L378)、[完整配置节点来源解析:517](https://github.com/cliouo/proxymanager/blob/1629959de83f30926b12197b364657817e8c296e/web/lib/engine/resolve.ts#L517)。

用户在“分发设置”中关闭“公开访问”，真实请求却是对订阅本身 PATCH `{enabled:false}`。enabled 同时参与 Profile 渲染和聚合成员选择，不是独立的分发权限。直接绑定该来源的 Profile 无法在禁用来源后正常渲染，因此预检可能拒绝操作；聚合场景也可能改变可用成员。

当前文案只解释“链接对外 404”，没有表达这些影响。建议改成“停用订阅源”并展示使用范围，或者引入独立的分发开关。仅想停止节点链接公开访问的用户，应能预先理解该操作对已有配置的影响。

**U05 · 浏览器扩展应明确规则写入哪份 Profile**

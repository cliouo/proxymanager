**实施方式说明**

- Web 在共用 `api` 入口为配置接口绑定当前标签页已确认的 ID，AI 可显式传入单轮 ID；避免各页面独立遗漏参数。`sessionStorage` 仅保存选择的 ID，未新增 YAML/凭证草稿持久化。
- 顶栏通过 `PageChrome` 提供主要/次要操作字段，并归类已有直接按钮，兼容现有页面声明。
- 模态行为使用共享 `useModalSurface`，保留现有面板 DOM 与分发 Portal。这样无需因桌面/手机容器变化而重新挂载编辑器或 AI 流；焦点、背景不可交互、最上层 Escape 和滚动锁定由同一入口管理。
- 新排序/移动路径沿用现有最终配置预检与版本 CAS。未放宽 MATCH、共享来源、设备覆盖或无缓存副作用约束。整体排序事件不提供不安全的逐实体逆向操作。
- 规则集的零引用与未知状态明确限定为“当前配置”；全局删除约束仍由服务端验证。

**接口与兼容**

- 优先使用 `?profileId=<UUID>`。兼容旧 `profile` 名称和省略参数时的 cookie/default；显式非法 ID、空名称或 ID/名称冲突不回退。
- `GET /api/v1/meta` 增加 `data.capabilities.profileIdScope: true`。
- 新增 `GET /api/v1/rules/summary`、`POST /api/v1/rules/{id}/move`、`POST /api/v1/proxy-groups/reorder` 与订阅/聚合的 `/{id}/usage`。
- 规则和策略组列表增加对应稳定读取的 `meta.configVersion`；排序/移动必须传 `expectedVersion`，冲突返回 412。
- 重复规则 ID 的批次现在返回整批 422；同一实体多个字段请合并成一个 update。
- OpenAPI 已同步。发布顺序为 Web/API 在前、扩展在后；扩展遇到无 ID 作用域能力的服务器会停止写回。
